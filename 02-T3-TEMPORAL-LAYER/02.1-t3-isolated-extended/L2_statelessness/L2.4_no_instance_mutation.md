# L2.4 — No instance-state mutation across calls (runtime test plan + L2.1 structural confirmation)

> **Status:** structural confirmation from L2.1 + runtime test plan (skeleton).

## Claim

> `extractor.extract(A); extractor.extract(B); extractor.extract(A)` → first and third calls produce bit-identical output.

If `extract(B)` mutates instance state, the third call could differ from the first. L2.1 AST audit (Pass 2 strict scan) **proved that no method on any h3 class mutates instance state outside `__init__`** — therefore L2.4 is structurally guaranteed.

## Structural confirmation (from L2.1)

Pass-2 strict scan result:

> Total `self.X = ...` assignments outside `__init__` / `__post_init__` across all 15 classes and all method types: **0**.

This means no method anywhere in h3/ — including `extract`, `execute`, `compute`, `compute_weights`, `select`, `build`, helper methods, properties, and dunder methods — writes to `self.anything`. Two calls cannot diverge from each other through instance state, because the instance has no mutable state beyond construction.

## Test outline (runtime confirmation)

```python
extractor = H3Extractor()
demand = build_full_demand()

A = make_canary_input(seed=42)
B = make_canary_input(seed=137)

out_A1 = extractor.extract(A, demand)
out_B  = extractor.extract(B, demand)
out_A2 = extractor.extract(A, demand)

for tuple_key in out_A1.feature_map:
    assert torch.equal(out_A1.feature_map[tuple_key], out_A2.feature_map[tuple_key]), \
        f"Instance-state mutation violated at {tuple_key}"
```

## Acceptance criteria

- For all ~644 active demand tuples, `out_A1 == out_A2` bit-identically.
- Repeat for 100 random A/B pairs.

## Verdict

**PASS by L2.1 structural guarantee.** Runtime confirmation skeleton is the empirical complement; expected PASS by construction.
