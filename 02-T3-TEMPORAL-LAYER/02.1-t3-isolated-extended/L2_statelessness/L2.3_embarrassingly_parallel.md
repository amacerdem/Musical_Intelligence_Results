# L2.3 — Embarrassingly-parallel property (runtime test plan)

> **Status:** test plan (skeleton). Runtime implementation deferred.

## Claim

> Outputs at frames `t1`, `t2` (non-overlapping windows) are independent: serial vs parallel computation produces `max-abs-diff = 0`.

Because no method on any h3 class mutates instance state after construction (L2.1), frame-by-frame computations are independent by construction. L2.3 is the empirical confirmation under serial vs multi-threaded execution.

## Test outline

```python
extractor = H3Extractor()
r3_features = make_canary_input(T=10000)  # long enough for non-overlapping windows
demand = build_full_demand()

# Serial: full sequence
serial_out = extractor.extract(r3_features, demand)

# Parallel: split frames into chunks, process via N threads, concatenate
chunks = split_non_overlapping(r3_features, n_chunks=4)
parallel_outs = thread_pool.map(extractor.extract, chunks, demand=demand)
parallel_out = concat(parallel_outs)

assert torch.equal(serial_out.feature_map, parallel_out.feature_map), \
    "Embarrassingly-parallel property violated"
```

## Caveat — chunk boundaries

When chunking by non-overlapping frames, the chunk boundary may sit inside a horizon window (especially Macro/Ultra horizons that span seconds-to-minutes). For the embarrassingly-parallel property to hold strictly:
- Either chunk size > maximum horizon window (Ultra: H31 = 168,999 frames at 172.27 Hz = 16.4 minutes — impractical for chunking),
- Or each chunk reads its full window from the original input (overlap-aware chunking).

The test should distinguish:
- (a) **Strict statelessness**: same window content → same output (L2.2 covers this);
- (b) **Strict frame-independence at non-overlapping chunks**: requires window awareness.

## Acceptance criteria

- For all 32 horizons and 24 morphs, serial vs overlap-aware-parallel produces `max-abs-diff = 0`.
- For non-window-aware chunking, document the expected discrepancy at chunk boundaries (it is not a state violation; it is the natural windowed-aggregation boundary effect).
