# L2.5 — No R³ frame-state leakage (runtime test plan)

> **Status:** test plan (skeleton). Runtime implementation deferred.

## Claim

> Truncate input at frame `T`; verify T³ output at every frame `t < T - max_window` is bit-identical to the same frame in the untruncated input.

This tests **causal-window honesty**: a Memory-law (L0) operator at frame `t` must read only `[t-h, t]` and never glimpse `[t+1, ...]`. Truncating the input after frame `T` should leave outputs at frames `t ≤ T - h` unchanged for L0; outputs at frames `t > T - h` are window-truncation casualties (expected).

For Forward law (L1) and Integration law (L2), the truncation footprint is different (L1 reads `[t, t+h]`; L2 reads `[t-h/2, t+h/2]`), and the test must adjust the comparison frame range accordingly.

## Test outline

```python
extractor = H3Extractor()
demand_L0 = build_demand_filtered(law=0)  # Memory only
T_full = 10_000  # frames
T_truncate = 5_000

r3_full = make_canary_input(T=T_full)
r3_trunc = r3_full[:T_truncate]

out_full = extractor.extract(r3_full, demand_L0)
out_trunc = extractor.extract(r3_trunc, demand_L0)

# Check: for each L0 demand tuple at horizon h,
# frames t in [h-1, T_truncate-1] should match in both runs
for tup in demand_L0:
    h = tup.horizon_frames
    safe_range = (h - 1, T_truncate - 1)
    diff = (out_full.feature_map[tup][safe_range[0]:safe_range[1]] -
            out_trunc.feature_map[tup][safe_range[0]:safe_range[1]]).abs().max()
    assert diff == 0, f"Frame-state leakage at {tup}: max-abs-diff = {diff}"
```

## Acceptance criteria

- For all L0 (Memory) demand tuples, output frames in the safe range match bit-identically.
- For all L2 (Integration) tuples, the safe range is `[h/2, T_truncate - h/2 - 1]`.
- For all L1 (Prediction/Forward) tuples, the test is reversed: prefix-truncating the input should leave outputs at frames `t ≥ h - 1` unchanged.

## Why this matters

This is the **frame-locality** counterpart of R³'s Rule 1 (frame-locality of R³ outputs). If T³ accidentally peeked beyond its declared window, it would constitute prediction-from-future or memory-from-future — violating the L0/L1/L2 partitioning that the predictive-coding interpretation relies on.
