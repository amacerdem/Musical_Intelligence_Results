# L2.2 — Window-content purity (runtime test plan)

> **Status:** test plan (skeleton). Runtime implementation deferred.

## Claim

> Same window content across two calls → bit-identical output.

If the AST audit (L2.1) holds (no instance mutation after construction), this is structurally guaranteed. L2.2 is the runtime confirmation: instantiate one `H3Extractor`, call `.extract()` twice on byte-identical inputs, assert outputs are bit-identical (`max-abs-diff = 0` over the full demand registry).

## Test outline

```python
extractor = H3Extractor()
demand   = build_full_demand()  # ~644 mech-only tuples or ~8,600 full registry
r3_features = make_canary_input()  # fixed-seed analytical stimulus

out_a = extractor.extract(r3_features, demand)
out_b = extractor.extract(r3_features, demand)

for tuple_key in out_a.feature_map:
    assert torch.equal(out_a.feature_map[tuple_key], out_b.feature_map[tuple_key]), \
        f"Window-content purity violated at {tuple_key}"
```

## Acceptance criteria

- For all ~644 active demand tuples (mech-only registry) and all ~8,600 (full registry), `out_a == out_b` bit-identically.
- Repeat across 100 random-seed canary inputs (still single-extractor, two consecutive calls).

- **L2.1 AST audit** structurally guarantees this — no `self.X = ...` assignment outside `__init__` means there is nothing for the second call to read from the first call.
